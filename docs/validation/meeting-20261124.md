The six stock-core skips are tests of the new execution API. They all run with
the modified local core; they are not six unexamined scenarios. Dependencies
were reused from the existing `avlite-carla` environment; this was not a clean
OS/dependency installation. The short repeated drives are coordination checks,
not independent traffic or perception-accuracy benchmarks.

The factory check explicitly enables perception: the standard asynchronous
executor defaults this step argument to false. Selection requests can finish
through the task event queue, so the test waits for a new result instead of
reading the previous selection immediately after submission.

Candidate construction initially exposed a rollback gap: a failing constructor
could mutate the active PM. Candidates now use an isolated PM snapshot. A test
mutates the candidate's observations and fails construction, then checks that
the original route, observations and planner remain unchanged. Observation reset
is also tested on the stock-compatible executor.

## Reproduce

Run the plugin suite from the parent development checkout:

```bash
PYTEST_DISABLE_PLUGIN_AUTOLOAD=1 python -m pytest \
  --rootdir=. --import-mode=importlib -o addopts='' -q avlite-behavior-hdmap/tests
```

For the agent checkout, replace the final path with `agent-plugin/tests`.
`PYTEST_DISABLE_PLUGIN_AUTOLOAD` avoids unrelated user-site pytest plugins; it
does not disable any tests in these suites.

From the plugin directory, using a fresh temporary directory:

```bash
check_dir=$(mktemp -d)
python tools/prepare_coordinator_profile.py --mode race \
  --executor AsyncThreadedExecuter --output "$check_dir/race-threaded.yaml"
AVLITE_CONFIG_DIR="$check_dir" python tools/check_coordinator_profile.py \
  --profile race-threaded --output "$check_dir/result.json"
python tools/coordinator_demo.py --mode both --repeat 3 \
  --output "$check_dir/handovers.json"
```

The profile checker accepts a profile name, not a YAML pathname. For ordinary
executors, use the matching local core. Stock 0.6.7 uses `PlanningSyncExecuter`.

Evidence is saved in the parent workspace at `logs/majid_followup_20261124/`.
The core-only diff is `releases/majid-followup-20261124/core-execution-api.patch`.
Its manifest records the development baseline hashes. It is not a patch against
pristine upstream: this checkout already contained earlier core changes.

## Remaining integration boundaries

The shared core type names and ownership are still a proposal for maintainers.
No new detector selector or closed environment-type enum was added. Final ROS
wire encoding and multi-producer observation channels require agreement.

Remote ROS stack replacement needs worker-side publication and acknowledgement;
a local pointer swap would only change the display mirror. The base boundary
rejects that unsupported operation. The ROS check above covers existing argument
forwarding, not live distributed planner replacement.

Parking missions and experimental before-step hooks still use the runtime
adapter. No claim is made that every plugin feature now works with every
executor. No new CARLA or real-camera accuracy run was performed for this API
refactor. Nothing was committed, pushed or sent to the team.
